# yunzhi · 入口：新建项目、接着做

> 命令规矩见 AGENTS.md 第一节：`$PY` 换成 `py -X utf8`（Windows）或 `python3 -X utf8`（macOS / Linux）；所有命令在工作区根目录下跑；路径参数加双引号。下面的 `<项目名>` 换成 `projects/` 下那个项目文件夹的名字。

## 先判断是哪种情况

每次对话开始，先按 AGENTS.md 第〇节跑一遍环境检查（`$PY "agent-tools/env_check.py"`），没问题再往下走。**一个对话只跑一次**：同一个对话里再进这份说明不用再跑（第三轮实测跑了 6 次），只有用户说装了东西、改了设置才再跑。这份说明本身也一样：同一个对话里读过就记住，不用反复重读（上下文被压缩过之后例外，见 AGENTS.md）。

- 用户贴了一段委托（要研究什么、交什么），或者说「新建项目」→ 做第一节「新建项目」。
- 用户说「接着做」「继续」「做到哪了」，或者这是一个新对话、你不知道在哪一步 → 做第二节「接着做」。
- 已经在某个项目里、知道在哪一步 → 直接加载那一步的 skill（见 AGENTS.md 第二节的表）。

## 第一节 新建项目

1. **定项目名**：取委托的主题，一句短语，20 个字以内，不带标点，例如「新能源汽车下乡与县域充电设施」。用户说了项目名就用用户的。
2. **存委托原话**：用写文件的工具（Codex 用 `apply_patch`）把用户发来的那条消息**整条、一字不改**写进 `projects/_inbox/<项目名>/request.md`（`<项目名>` 就是上一步定的名字：每个新项目自己一个暂存文件夹，几个对话同时新建项目不会互相覆盖；直接放在 `projects/_inbox/` 下面的，脚本不收）—— 开头的「新建项目：」之类也留着，不删字、不加标题行、不加你自己的话（第三轮实测：删了开头、加了一行标题，委托原话就不是原话了）。项目名用下一步的 `--title` 给，不写进委托原话；委托原话第一行是标题（`#` 开头）时，脚本不建项目。
3. **材料**：用户附了文件，记下每个文件的完整路径；用户把材料文字直接贴在对话里，就把那段文字原样存成 `projects/_inbox/<项目名>/<材料名>.txt`，当作一个文件。没有材料就跳过。这里只放用户给的材料；你自己从网上找的资料，到收集资料那一步再存（见 `evidence-card`）。
4. **建项目**（每份材料一个 `--material`，没有材料就不写）：

```
$PY "agent-tools/projects.py" new --title "<项目名>" --request-file "projects/_inbox/<项目名>/request.md" --material "<材料文件 1>" --material "<材料文件 2>"
```

5. 照输出做：
   - 这个对话里第一次打开这个项目：用 `yunzhi-progress` 第 1 节把右侧挂上（地址是输出里的 `pane_url`）。之后右侧显示什么都由脚本换，不再挂。
   - 把输出里的 `say` 原样告诉用户（项目建好了、项目名是什么、不合适可以改、每份材料转换得怎么样）；不贴路径。
   - 加载 `task-planner`，从「第 1 步 开场：一次问完」开始。新建项目这一条消息不用记进用户消息（委托原话已经存好了）；从下一条用户消息起，每条都先记（AGENTS.md 第三节第 6 条）。
   - **`say` 那句和开场「一次问完」的问题写在同一条回复里，问题就是普通对话**：直接写在回复里问，**不调 `request_user_input`**（选项框只用来发 `card.py prepare` 准备好的卡；开场问题没有卡，守门脚本会拦。第八轮实测：调了被拦，退回对话里再问，「项目建好了」就说了两遍）。
6. 用户要改项目名：`$PY "agent-tools/projects.py" rename "<项目名>" --to "<新名字>"`。右侧那一页跟着搬了家，按 `yunzhi-progress` 第 1 节用输出里新的 `pane_url` 重新挂一次。以后命令里都用新名字。

## 第二节 接着做

1. 列出项目：

```
$PY "agent-tools/projects.py" list
```

2. 照输出：
   - 0 个项目 → 请用户贴委托（和材料），然后做第一节。
   - 1 个项目 → 直接做第 3 步。
   - 不止一个 → 按 `yunzhi-card` 出一张选项目的卡：`$PY "agent-tools/card.py" prepare pick_project`；回答写进 `projects/_inbox/选项目/answer.txt`，跑 `$PY "agent-tools/card.py" answer --card pick-project --answer-file "projects/_inbox/选项目/answer.txt"`（这张卡不带项目名），输出里的 `project` 就是用户选的项目。
3. 看这个项目在哪一步：

```
$PY "agent-tools/projects.py" status "<项目名>"
```

4. 照输出的 `next` 做，规则是：
   - `consistent` 为 false（进度和文件对不上）→ 停下。说「进度记录和文件对不上，我先停在这里，请你看一下。」再用一两句话说清是哪份材料（看 `problems`，换成用户的说法），等用户定，不推进。
   - `flow_change_pending` 为 true → 改流程卡还在等用户：加载 `task-planner`，按「变更与重新确认 · 只改流程」第 5 条再出一次改流程卡。
   - `pending_card` 不为空 → 有一张卡还没回答：加载 `skill` 字段说的那份 skill，重新出这张卡。
   - 其余 → 加载 `skill` 字段说的那份 skill，从那一步接着做。
5. 这个对话里还没挂过右侧：用 `yunzhi-progress` 第 1 节挂一次（地址是输出里的 `pane_url`）；这个对话里已经挂过就不再挂，脚本已经把右侧换成了进度页。
6. 把输出里的 `say` 告诉用户（现在在哪一步），可以再接一句接下来做什么，例如「现在在第 2 步：收集资料，正在收集资料。上次做到资料卡片 11 张，我接着找。」（数字照进度页或脚本输出里的写，不要自己数。）

## 对用户说话

- 用户是研究员，不是开发者。不说文件名、文件夹名、脚本名、英文词；说「项目」「委托原话」「材料」「进度页」。
- 材料转换的四种结果照这四句说：已转成可读的文字 / 没能读出文字（可能是扫描件或空表），原文件已保存 / 自动转换没有成功，原文件已保存 / 这种格式暂时不能自动转换，原文件已保存。
- 新建项目后这样说：「项目建好了：新能源汽车下乡与县域充电设施（名字不合适可以随时改）。你给的两份材料都已转成可读的文字。右侧是这个项目的进度。」
- 有几个项目时这样说：「你现在有 3 个项目，接着做哪一个？」然后出选项目的卡。
- 进度和文件对不上时这样说：「进度记录和文件对不上，我先停在这里，请你看一下。」
