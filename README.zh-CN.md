# 云织 Agent

[English](README.md)

云织 Agent 是面向政策、公共部门与产业经济研究员的研究助手，运行在 OpenAI Codex 里。

你用平常的中文交给它一个研究委托。它带着项目走完四步——明确任务、收集资料、拟定提纲、撰写交付——每到关键处请你确认。交付的是一份 Word 文档和一份网页，里面每个论断都能追到来源。

> **状态：** v0.1。
> - 在 Windows 11 上测试过：Codex 桌面版 26.930、Codex 命令行 0.160；模型用过 GPT-6.1 Sol 和 GPT-5.6 Terra。
> - 助手用中文和用户说话。

## 它做什么

- **四步：** 明确任务 → 收集资料 → 拟定提纲 → 撰写交付。
- **确认：**
  - 你要确认任务计划、资料汇编和提纲，最后确认交付。省掉提纲这一步的项目，交付前确认两次。
  - 每次确认都是一张选项卡：Codex 原生的选项卡，或者对话里带编号的文字卡。
  - 没有你的回答，不往下走。
- **两种简报：** 一种对一个明确的判断按事先定好的标准去验证；一种只梳理情况、不下结论。
- **资料卡片：**
  - 每个来源都要读过，记成一张卡：原文摘录、立场（支持、不支持、背景）和位置。
  - 专门检索反面证据。
  - 资料有缺口时，助手先停下来，问你怎么处理。
- **独立复核：**
  - 交付前，另起一个复核助手，拿成稿逐段对照来源核查。
  - 起它的时候不带写作过程的对话。
- **脚本检查：** 引用、一致性和格式都由脚本检查。Word 版和网页版由同一份底稿生成。
- **进度：** Codex 右侧挂着一页进度，由脚本随时更新。

## 怎么搭起来的

| 路径 | 内容 |
|---|---|
| `AGENTS.md` | 工作规则（Codex 和 WorkBuddy 共用） |
| `.agents/skills/` | 八份 skill：入口（`yunzhi`）、四步（`task-planner`、`evidence-card`、`outline-cocreate`、`cite-trace`）、复核（`review-module`）、选项卡（`yunzhi-card`）、进度（`yunzhi-progress`） |
| `agent-tools/` | 助手调用的 Python 脚本：项目、选项卡、进度、复核、取资料、链接检查、归档，以及守门脚本 |
| `toolkit/` | 研究工具包：规格（`04-正本规格-v1.md`）、检查脚本、网页版和 Word 版生成脚本、确认记录 |
| `wording/` | 词表和禁用词表，让内部用语不出现在用户看得到的地方 |
| `.codex/config.toml` | 工作区设置：Windows 沙盒方式、原生选项卡，并关掉这个工作区用不到的插件 |
| `.codex/hooks.json` | 守门 hook（见下） |
| `tests/` | 测试和变异检查 |

计数、排版、检查都交给脚本，不靠模型现场发挥。

## 守门 hook

你在 Codex 里批准这个工作区的 hook 之后，`agent-tools/hook.py` 会强制做到这些：

- **你的原话：** 你发的每条消息都由 hook 逐字记下。卡上引用你的话、你对卡片的回答，都拿这份记录核对。
- **选项卡：**
  - 原生选项卡必须对得上脚本准备好的卡，才弹得出来。
  - 不等回答的 `request_user_input_async` 工具一律拒绝。
- **确认记录：** 只能经出卡脚本写。直接改记录文件或确认字段，一律拒绝。
- **复核：** 起复核助手必须带 `fork_turns: "none"`，主助手也不能给它发消息。
- **最后一条回复：** 每轮最后一条回复都会扫一遍，查内部文件的链接、skill 名称和内部用语。不合格就打回去重说一次。

没批准时 hook 不会运行，助手只按写下的规则做事。

## 需要什么

- Windows 10 或 11（在 Windows 11 上测试过）。macOS 见「局限」。
- Python 3.10 或更高（在 3.12 上测试过），能用 `py` 启动器调用。
- `toolkit/requirements.txt` 里的 Python 包：PyYAML、python-docx、pypdf。
- OpenAI Codex 桌面版（在 26.930 上测试过）或 Codex 命令行（在 0.160 上测试过）。从 26.930 起，Windows 开始菜单里桌面版显示为「ChatGPT」。

## 开始使用

1. 把这个仓库克隆到本地。
2. 装 Python 包：`py -m pip install -r toolkit/requirements.txt`。
3. 在 Codex 桌面版里把这个文件夹作为项目打开，询问时选择信任。只有被信任的文件夹，项目设置和 hook 才会加载。
4. 新开一个对话。第一次时，Codex 会请你审核这个工作区的 hook：批准它们。
5. 发送 `新建项目：<主题>。<你要什么，比如篇幅和读者>`，有材料就一起附上。
6. 卡片来了就回答。
7. 以后要接着做某个项目，新开一个对话，说「接着做」。

项目放在 `projects/<项目名>/` 里，git 不会收录这个文件夹。做好的文件在 `projects/<项目名>/out/`。

## 怎么回答选项卡

- 点选项，或者在对话里回选项前面的数字。
- 要补一句意见，写在数字后面，例如 `2，时间段改成从 2021 年开始`。
- 只写意见不算确认；准备好了再回数字。
- 原生选项卡如果一直没人回答，大约三分钟后 Codex 会把它收起。直接回选项前面的数字就行。

## 局限

- **平台：**
  - 只在 Windows 上测试过。`.codex/hooks.json` 调用的是 `py`，所以在 macOS 上，要把命令改成 `python3`，hook 才会运行。
  - WorkBuddy 的支持已经备好（`.codebuddy/skills/`，由 `agent-tools/sync_skills.py` 同步），但还没测试。
- **hook 做不到的：**
  - 最后一条回复的检查只看得到每轮的最后一条，而且是在它显示出来之后。工具调用之间的过程消息，只能靠写下的规则。
  - shell 守卫只认明显的写法。它防的是失误，不是安全边界。
- **Codex 的行为：**
  - 对话里的进度快照已经关掉，因为 Codex 26.930 把它显示成了原始文字。进度改在右侧看。
  - 在 Codex 新对话里选模型，会连带改掉你的全局默认模型。这是 Codex 的行为，不是本项目造成的。
