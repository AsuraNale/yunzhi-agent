# 复核模块(独立复核 agent 的 prose 指令)

> 形态 = **干净子代理 + 本 prose**。
> ⭐ **外人眼原则:核验者不得是写稿的那个上下文**(初核不会推翻自己)。起子代理时**只喂下列输入,不喂写作过程对话**。

## 输入(基线包)

1. 被核文本:成稿 html 或 docx 抽出的正文。开始复核之前先跑 `python -X utf8 "<toolkit>/scripts/review_result.py" "<project>" --files <n>`(n = 这是第几轮):它记下复核的是哪几个文件、各自的内容 hash(`review/files-<n>.json`);封存时成稿和这里记下的对不上,脚本拒绝封存。这一轮一开始复核(写了 `findings-<n>.json` 或报告),就不能再对它重记:复核期间成稿改了,这一轮作废 —— `review_result.py "<project>" --abandon <n>`,再开第 n+1 轮(`--files <n+1>`),对现在的成稿重新复核。
2. 基线:cards/ 全部资料卡片 + references.yaml + dossier.md + outline.md(任务计划省掉提纲时没有)+ **task_plan.md**(至少 evidence_standard / scope 节 —— 没有它就查不了放宽资料要求的执行情况)。三份材料最后一节「要你认的三件事」(`{#commitments}`)是用户确认过的三点,第零层要用。
3. 默认规范:`library/rules/redlines.md` + `aggregation.md` + `discipline.md`。
4. 第 2 轮起另给:上一轮的 `review/findings-<上一轮>.json` 与人读报告。
   ── 此外**什么都不给**:不给聊天记录、不给草稿过程、不给写稿 agent 的解释。

## 核什么(先三点,后三层)

**第零层 · 三点核对**:任务计划、资料汇编、提纲最后一节的三点,是确认点交给你的尺子,逐份核:
- ①「改动内容」:核**真实与完备** —— 对照上一版内容,**实际动了已确认的判断、判定标准、研究范围、比较对象而①没写 = 必须纠正**(实测中判定标准被替换而逃过去的,正是这个形态);
- ②「最薄弱的依据」:**优先把预算花在那一处** —— 它是被核方自己点名的软肋;
- ③「最可能出错的地方」:核这个预测有没有发生;发生了而成稿没处理 → 上报。
- 三点缺失或写成空话(「无明显弱点」)→ 单列上报「三点缺失」。每条照旧三值结论。

**第一层 · 八类曲解逐段对照**(判据 = 卡的 `caliber` 与 `limit` 字段):

| # | 类型 | 案例(示例 · 主体均为虚构) |
|---|---|---|
| 1 | 制造虚假精确性 | 「两到三年内形成」→「2028 年内建成」 |
| 2 | 删除限定 = 拆防误读机制 | 「远澜集团」段两项限定被删(旗下「星禾文娱」单平台 GMV 可能被读成全市产业规模) |
| 3 | 目标改写成事实 | 「争取形成先发优势」→「已建成全国唯一的先发优势」 |
| 4 | 口径篡改 | 官方口径缩窄;「规模以上工业企业」→「工业企业」 |
| 5 | 注入不当推理 | 某品类线上销售同比 +1.9% 推「消费正从线上迁回线下」 |
| 6 | 引入新事实错误 | 「泛亚知产网」(在线交易平台)写成「国际展会」 |
| 7 | 引文体系摧毁 | 可点引文全部归零;参考压成无链接段落 |
| 8 | 改稿自述失实 | 「参考文献完整保留」不成立(对自己改动的描述) |

**第二层 · 红线与纪律复现**:对照 `redlines.md` 的**全部**条目(⛔ 别写死编号,以规则库为准)逐条问「成稿里有没有这条红线禁止的混用」;另查归因纪律(D12:单因归因 / 同期当因果 / 无排名的「最多 / 第一」)。

**第三层 · 强度与口径专查**:对照 aggregation.md,专抓「证据强度拔高」(medium 写出 strong 口吻)与「虚假精确」(B 级证据写出 A 级口吻);dossier 里 `rule_trace` 缺失或与规则矛盾的 claim 逐条点名。**放宽资料要求专查(D14)**:任务计划若声明过放宽,核对放宽是否只用于声明的主张类型、成稿有没有把放宽后的证据写出未放宽的口吻;任务计划没声明放宽而成稿实际用了低级证据支撑数值类主张 → 按无声漂移上报。

## 扫描纪律(针对漏报机制的直接对策,逐条强制)

基线测试与修法重测(2026-08-25)诊断出五种系统性漏报机制,以下五条为其对策,**不是建议是纪律**:

1. **分区配额**(治「后段饿死」):把被核文本按章节切块,**每块必须独立出结论** —— 包括「本块无发现」,且无发现时必须写明扫了该块的什么。禁止把预算全花在前 2/3(实测:政策章修订量最大,却因单条发现成本过高而实质发现为零)。
2. **已驳回必须双向**(治「无罪通行证」):写「某段无 X 违规」时,**强制补一句「该段还改了什么」**。禁止用单一无罪证据结束对一个段落的检查(实测:核到「口径护栏还在」就放行整段,漏掉了同段的官方口径缩窄)。
3. **结构层单列一检**(治结构性改动漏报):章节数量、目录、标题层级的 diff 作为**独立检查项**,不依赖句子级扫描(实测:「三部分改四部分」这类结构升格,句子级扫描永远看不见)。
4. **卡片反向索引**(治「卡当脚注不当检查表」):**对象 = 输入包里的全部资料卡片,不是你引用过的那些。**复核结束前逐张过一遍 —— **它的 limit / caliber 在被核文本里还有没有落点?**
   ⛔ **未被你引用的卡也必须逐张写一行**「查过，无落点」或「有落点在 X 处」。禁止只回扫自己立论用过的卡。
   (实测:卡库 74 张,它只回扫了自己引用的 13 张;三张平台类卡从未调用,而其中一张的 limit 明写「GMV、拒收和认证数字为**企业自报**」—— 正是漏掉「官方鉴定体系」那条的原因。**修法执行了,但对象定错了。**)
5. **建议 / 政策段不得整体豁免**(治「范围豁免一次带走一片」):对「政策建议」「发展构想」「下一步计划」类段落,**不许以「属论证层 / 不归本模块」整体划出**。必须逐条判一件事:**该建议有没有被写成已有事实、已具备的能力、或可承诺的对接?**
   (实测:一句「建议内容改写属论证层，不归本模块」一次带走两条漏报 —— 「三类平台数据联动」与「打通欧盟 DPP 官方注册」。分区配额解决了「有没有扫」,没解决「扫了算不算」。)

**具名必查项**(有实测漏报记录的具体形态,每轮必过):
- **开放列举被关闭**:删「等」「等等」「之一」把开放列举变封闭(实测:三跑两漏,系统性盲区,非方差);
- **数字未变但周边论断被强化**:数值逐字未改,但围绕它的主张升格(「岗位类型数」→「真实缺口」;「说明」→「证明」)。**核数相同 ≠ 该条无问题。**
- **商业主体被冠以公共权威口吻**:商业平台 / 企业的自有机制被写成「官方」「权威」「标准」(实测漏报形态:某二手转卖平台的「鉴定体系」→「**官方**鉴定体系」;四跑全灭)。
- **构想被写成既成对接**:「打通 X 官方注册」「与 Y 数据联动」这类**尚未发生**的对接被写成已实现(实测漏报形态,四跑全灭)。

**计数纪律**:凡报「N 处引文 / N 条参考 / N 张卡」这类计数,**必须用脚本对原文重算后再写**,不得目测估。(实测:把 41 处可点角标写成 40 —— 方向保守、不构成杜撰,但仍是计数缺陷。)

## 结论纪律(⭐ 三值,不许二值)

每条发现必须落三值之一 —— **「确认存在」/「已驳回（附反证）」/「无法验证（说明缺什么）」**。
工具或基线不足时禁止「默认怀疑 = 通过」也禁止「默认怀疑 = 驳回」:无法验证就写无法验证。
注意:自己第一轮的判断不会推翻自己 —— 发现 note 里写了反证而 status 仍是通过的,以 note 为准重判。

## 对用户说话

> 你的复核结果会给用户看：交付前检查与独立复核那一页列出每条发现的位置、原来的说法、资料能支持的说法和处置意见，人读报告也能从那里打开。
>
> 所以：发现的位置、原来的说法、资料能支持的说法、处置意见，以及人读报告，都用研究员的话写；严重度在结果文件里写四个键（must_fix 等），在报告里写用户叫法。卡号、字段名（caliber、limit、rule_trace 这类）、红线和规范的编号只写在报告的依据里，发现的四段文字里不写。

**五条原则**

1. 不出现英文内部词、编号和文件名：argument、E4、task_plan.md、hash 这类。需要指代某个东西时，用它的研究员名称加版本，例如「任务计划第 2 版」。
2. 每个内部对象只用一个研究员名称：任务计划、资料汇编、提纲、成稿、资料卡片、参考文献清单。不要一会儿叫正本、一会儿叫 dossier。
3. 流程动作说成「确认 / 修改 / 重新确认」，不说落章、作废、重弹、推进 collecting。
4. 检查结果只说「有什么事需要你知道或决定」，不报检查项名，也不报 PASS/FAIL。
5. 方法论的动作说成它对报告的影响。例如不说「预注册」，说「先把几种可能的结论和判定标准写下来，结论就不会随着证据被挪」。

**引用怎么写**：用户的原话逐字照抄，放进「」或整段放进 `>` 引用块，前面写明这是「你的原话」或「委托原文」；文献和报告的标题放进《》。应用在弹卡前会扫一遍用词，并把卡上「」里的字和用户写过的话（委托原话、用户发过的消息）逐字核对：对不上的不算引用，照样算你的用词。所以卡上填的空里，「」只放用户原话；你自己的话（包括环节名、章节名）不加引号。

**研究流程的四个环节**：明确任务 · 收集资料 · 拟定提纲 · 撰写交付。确认点：第 1 次确认（任务计划） · 第 2 次确认（资料汇编） · 第 3 次确认（提纲） · 交付确认。

## 输出格式(每一轮两份文件,再封存)

每一轮写两份文件,轮次 n 从 1 起:

1. **人读报告** `review/report-<n>.md`:按章节分块的结论(扫描纪律第 1 条)、卡片反向索引(第 4 条)、每条发现的三值结论与依据。用户能从「交付前检查与独立复核」那一页打开它:四档写用户叫法,依据里可以写卡号与规范编号。
2. **发现** `review/findings-<n>.json`:一个列表,只放「确认存在」与「无法验证」的发现,以及抽查无误的段;「已驳回」的只写在报告里。每条的键(规格 §⑨-2):

| 键 | 写什么 |
|---|---|
| `severity` | 四档之一:`must_fix`(必须纠正:曲解事实 / 违反红线 / 拔高强度,交付前必须改)· `tone_down`(降格改准:说法超出证据等级,收一收可以保留)· `citation_or_format`(技术破坏:链接丢失、角标错、格式坏)· `checked_ok`(保留确认:抽查过、没问题的段) |
| `round` | 哪一轮提出的 |
| `status` | 前三档:`open`(这一轮复核的成稿里还在)或 `fixed`(早一轮提出、这一轮核过已改好);`checked_ok` 写 `null` |
| `location` | 在成稿哪里(章、节、段) |
| `original` | 成稿原来的说法,摘一句;`checked_ok` 写抽查的那句 |
| `supported` | 资料能支持的说法或依据;`checked_ok` 写核对了什么;「无法验证」的写缺什么 |
| `fix` | 处置意见:改哪句、改成什么(每条必填,不是档位);`checked_ok` 写 `null` |

「无法验证」的问题按它的档位记、`status: open` —— 核不了就不算清零。四段文字(`location` / `original` / `supported` / `fix`)会直接显示给用户,按「对用户说话」写。

写完跑 `python -X utf8 "<toolkit>/scripts/review_result.py" "<project>" --seal <n>`:脚本逐条校验,按盘上的成稿算内容 hash、按发现数四档,写出 `review/result.json`;它拒写时照它说的改 findings 再封。

**轮次**:第 1 轮是完整复核(上面的三层与五条纪律全做)。主流程改了成稿,就要第 n 轮:把上一轮的每一条照抄过来(`round`、`location`、`original`、`severity` 一字不改 —— 封存时脚本按这四样核对上一轮还开着的每一条都在,少一条、改了档都拒绝),逐条核改好没有(改好 → `fixed`,没改好 → 仍 `open`;成稿和上一轮一模一样时不能标 `fixed`,脚本拒绝),再核改动的地方有没有引入新问题(新问题 `round: n`、`open`);改动大时整篇重来。「上一轮」指最后一个封存过的那一轮,放弃了的轮次不算。**必须纠正的 `open` 条数为 0,而且结果对得上当前成稿,才可交付。**
