# evidence-card · 第二步:收集资料

> 前置:任务计划已确认(`pipeline_status.py` 核);路径约定见 AGENTS.md。默认规范 = `<toolkit>/library/rules/` 四件(redlines 口径红线 · discipline D1–D17 · evidence-tiers A/A−/B · aggregation 聚合规则)。

## 你在哪

第二步。完成 = 资料汇编在确认卡上被用户确认。开场告诉用户:这一步做什么、大概怎么走、做到什么程度(说法见「对用户说话」)。

## 这一步怎么走 —— 自由,但有出口

**没有规定步骤。**采集顺序、扇出几路、先深后广还是先广后深、何时开始汇编 —— 你和用户商量着定,或按任务形态自己判断;用户中途想看卡、想调方向、想加一条线索,**照做**(资料汇编还没确认,改是免费的)。
唯一要求:**离开这一步时出口契约全满足**;过程中**手艺规范**(下)每一条都在场。

### 中途要用户拿主意:决定卡

碰到要用户定的事 —— 任务计划写过的中途检查点被触发、数据查不到、口径有两种都说得通的取法 —— 先发一句话说清卡在哪里,再调 `ann_gate_card`:

```json
{"id": "decision-2021-data", "kind": "decision", "question": "2021 年的分县充电桩数据查不到。增速从哪年开始算？", "why": "查过省统计局和能源局，都没有公布 2021 年的分县数据。不定下来，活动前后的对比就没法算。", "options": [{"label": "从 2022 年开始算", "effect": "少一年，但全是分县数据，结论最站得住。", "changes_plan": false}, {"label": "用全省数据补 2021 年", "effect": "年份完整，但 2021 年那段只能说全省，不能说县。", "changes_plan": false}, {"label": "改成梳理情况", "effect": "不下判断，只梳理现状。", "changes_plan": true}], "recommend": 1}
```

- `question` ≤40 字,必须是一个选择(不是「你怎么看」);`why` ≤80 字:卡在哪里、不问会怎样。
- `options` 2–3 个:`label` ≤20 字(做法)、`effect` ≤40 字(会怎样)、`changes_plan`(选了它要不要改任务计划,真或假)。`changes_plan` 为真的那一项,应用会在卡上加一句「会改任务计划，再请你确认」,`effect` 里不用再写。
- `recommend`:你建议的那一项,从 1 数;不建议就不写这个键。
- 一张卡只问一件事。只是要用户补一句话的普通问题(这家机构的全称是什么),不用卡,直接在对话里问。

回答是 `{id, kind, selected, custom?}`:`selected` 是用户选的那一项(从 1 数),应用已记下这次决定。照选的做,说一句接下来怎么做。决定的内容写进它影响的那份材料(例如资料汇编的资料缺口一节写「你决定：增速从 2022 年开始算」)。`selected: null` = 用户没点选项、只写了意见(`custom`):读意见,在对话里回应,还需要定就用同一个 `id` 再弹。选了 `changes_plan` 为真的那一项 → 按 task-planner「变更与重新确认」改任务计划、重新确认,确认之后回来接着收集。

### 用户说不要拟提纲

任务计划已确认、还在这一步(`collecting` / `gate2_awaiting`)时用户说「不用拟提纲了」→ 按 task-planner「变更与重新确认 · 只改流程」走改流程卡,确认之后回来接着收集。

### 资料汇编写好:弹资料汇编卡

1. 自查:`card_check.py "<project>/cards"` 与 `dossier_check.py` 无 FAIL;`python -X utf8 "<toolkit>/scripts/commitments_check.py" "<project>/dossier.md"` 退出码 0(研判型同时核上卡的那句理由);`node "<toolkit>/scripts/session_facts.mjs" --project "<project>" --json "<project>/out/session_facts.json"` 刷新会话事实(E4 的步数从这里抄;卡上「这一轮我读过的项目以外的文件」由应用自己列)。
2. `python -X utf8 "<toolkit>/scripts/stamp.py" "<project>/task_plan.md" --advance gate2_awaiting`
3. 发一句话:收了多少张资料卡片、几个是查过确实找不到的缺口、资料汇编第几版写好了。数字照自动统计的数写。
4. 调 `ann_gate_card`,只给 `id` 和 `kind`(`id` 写 `dossier-v<版本>`):

```json
{"id": "dossier-v1", "kind": "dossier"}
```

版本、资料卡片构成(支持判断 / 不支持 / 背景资料 / 资料缺口)、研判型的初步结论与理由、三点,都由应用从资料汇编与资料卡片读 —— 初步结论来自 frontmatter 的 `gate_verdict`:`reason` 那句理由直接上卡,≤60 字(规格 §③「上卡的字段」)。弹卡之后、用户回答之前别动资料汇编和资料卡片。

用户回答之后:**确认** → 应用已写确认记录、推进到拟定提纲(任务计划省掉提纲时推进到撰写交付);说一句交接的话,交棒 outline-cocreate(省掉提纲时交棒 cite-trace)。**先不确认**(`approved: false`)→ 照附言补资料或改结论,没附言就问要补什么、改哪条;改好:`version` 加一、`revision_log` 加一条、三点的改动内容写这一轮改了什么 → 回到第 1 步。卡被退回 → 照 task-planner「卡被应用退回」。

## 对用户说话

> 用户是政策、公共事务、产业经济方向的研究员，不是开发者。本节管你**对用户说出口的每一句话**：普通消息、对话里的提问、进度汇报、阶段交接，卡上留给你填的空，以及给用户看的材料里你自己写的句子。
>
> 本 skill 其余部分用的是内部叫法（文件名、字段名、状态名、脚本名）。干活、写文件、跑命令时照旧用；**说给用户时换成下面词表的右栏**。确认卡、决定卡上的问题、按钮和标签由应用写，你只填卡上留给你的空，填的空同样按本节写。

**五条原则**

1. 不出现英文内部词、编号和文件名：argument、E4、task_plan.md、hash 这类。需要指代某个东西时，用它的研究员名称加版本，例如「任务计划第 2 版」。
2. 每个内部对象只用一个研究员名称：任务计划、资料汇编、提纲、成稿、资料卡片、参考文献清单。不要一会儿叫正本、一会儿叫 dossier。
3. 流程动作说成「确认 / 修改 / 重新确认」，不说落章、作废、重弹、推进 collecting。
4. 检查结果只说「有什么事需要你知道或决定」，不报检查项名，也不报 PASS/FAIL。
5. 方法论的动作说成它对报告的影响。例如不说「预注册」，说「先把几种可能的结论和判定标准写下来，结论就不会随着证据被挪」。

**引用怎么写**：用户的原话逐字照抄，放进「」或整段放进 `>` 引用块，前面写明这是「你的原话」或「委托原文」；文献和报告的标题放进《》。应用在弹卡前会扫一遍用词，并把卡上「」里的字和用户写过的话（委托原话、用户发过的消息）逐字核对：对不上的不算引用，照样算你的用词。所以卡上填的空里，「」只放用户原话；你自己的话（包括环节名、章节名）不加引号。

**研究流程的四个环节**：明确任务 · 收集资料 · 拟定提纲 · 撰写交付。确认点：第 1 次确认（任务计划） · 第 2 次确认（资料汇编） · 第 3 次确认（提纲） · 交付确认。

**这一步常说的几句**

- 开场这样说：「现在是第二步：收集资料。按任务计划找资料，每条资料做一张资料卡片，最后整理成资料汇编，请你确认。」
- 汇报找资料的情况时，每条说清是哪种结果：已取得 / 查了但没有内容 / 没有这项数据 / 没取到（出错）/ 打不开；来源说成官方一手 / 机构自报 / 二手。
- 超出篇幅和工作量上限时这样问：「资料卡片已经做了 N 张，超过了任务计划里定的工作量上限，要继续，还是先收一收？」数字照实写，不提计数字段的名字。
- 卡住要用户拿主意时，先说清卡在哪里再弹决定卡，例如：「今天加了 11 张资料卡片。2021 年的分县充电桩数据查不到；任务计划里写过，碰到这种情况要停下来和你商量。」用户选了之后说接下来怎么做：「好，增速从 2022 年开始算。我接着找资料。」
- 决定卡上：问题写成一个选择；为什么要问写卡在哪里、不问会怎样；每个选项写做法和会怎样。
- 弹资料汇编卡之前：「资料收齐了：18 张资料卡片，其中 2 个是查过、确实找不到的缺口。资料汇编第 1 版写好了，请你看一下。」数字照自动统计的数写。
- 讲资料汇编时，四个部分叫：初步结论、适用范围与不能下的结论、检查点结论、来源清单；证据强弱说成证据充分 / 较充分 / 一般 / 不足。
- 资料汇编确认之后又要补资料时这样说：「要补资料的话，我补完会改好资料汇编，再请你确认一次。」
- 用户在这一步说不要拟提纲：「好。已写进任务计划第 3 版：本项目跳过拟定提纲，写作按资料汇编的结构走。这改动了你确认过的任务计划，要请你再确认一次。」

## 出口契约附注

**(E4) steps_used 取数**
⛔ **`steps_used` 从 DSH 会话日志取,不许自报**:`node "<toolkit>/scripts/session_facts.mjs" --project "<project>" --json "<project>/out/session_facts.json"` → `steps_used`(**主会话**的 `step/start` 计数;同一份 json 里另有 `steps_incl_subagents` = 含子代理,实测 255 / 536)。⛔ 写进 `dossier.dashboard` 时**同时记 `session`(会话 id)、`session_picked_by`(选法:env 注入 / 启发式)与取数时刻** —— 选法必须落到正本,否则启发式选错了,核对的人看不见。cite_check ⑧ 会拿这份 json 核你写的数,对不上判 FAIL。⚠ 早期规格曾记管线读不到 DSH 的步数事件 ——**那句是错的,已更正**:实测日志里有 255 个 `step/start`,而 dossier 的 `dashboard.steps_used` 写着 `null`、正文还写着 DSH 环境没有步数事件。取不到时写「未取到」并说明是哪一步没成,⛔ **不许写 0,也不许写"环境没有这个事件"** —— 那是把"我没去取"说成了"它不存在"。

**补充**:`取数时刻` 的键名固定为 `captured_at`(UTC ISO-8601);`session`、`session_picked_by`、`captured_at` 三项须与本轮 json 逐值同源,不能沿用另一轮。

⛔ **不给用户出题**(此前「事实题」把一条实测方向读反:那个数据点是**用户提供、agent 缺的信息**(用户是信息源),被误推成 agent 拿自己写的材料考用户(用户是考生)—— **给用户加负担不是优化**。正确方向 = 把材料呈现好,让用户自己看得懂)。

出口满足 → 交棒 outline-cocreate(任务计划省掉提纲时交棒 cite-trace)。

## 手艺规范(活动级不变量 —— 干到哪条守哪条,与顺序无关)

**采集(Fetch Honesty)**
- 抓**具体内容页**,不抓门户首页(会被截断);一手资料尽量引**存档型**出处。
- 每次抓取如实记五态 `ok | empty | gap | failed | blocked` —— **空≠失败,失败≠没有**;禁止把 failed 报成「查过了没有」;禁止用训练记忆冒充抓取结果。
- 「该数据不存在」本身是产出:立 `stance: gap` 卡(D5)。
- 快照纪律(D9):截止日之后发布的数据不提前使用;发现更新版数据,开新卡不改旧卡。

**落卡(边读边落,D1/D3)**
- 一卡一文件 `cards/<uid>.md`,一卡一断言;`facts = [{value, caliber, cited}]` 数值-口径成对,被直接引用的数字所在来源必带 `locator`。
- `stance ∈ support|counter|mixed|gap` 封闭四值(界面上依次叫支持判断 / 不支持 / 背景资料 / 资料缺口,资料汇编卡上的卡片构成就按这四类数;规格 §②);主题 `tags` 自由;`sources[].tier ∈ A|A-|B`(定级按 evidence-tiers.md,**混合级禁用**:取低值 + note 记差别);`as_of` 必填(D17)。
- 正文固定两节:`{#support}`(判读结论)与 `{#limit}`(**必填非空**,D4:口径/时效/利益相关/自报≠审计 D10/异常基期 D11;确无则写「无重大局限（理由）」)。界面上它显示为资料卡片的「不能说明」,交付前的独立复核也对照这一栏。
- uid 永不复用;更新走增量新卡,旧卡逐字原样(D9);弃用只标 `deprecated: true` 不删文件。
- ⭐ **沿用既有取证必须标 `inherited_from`**(如 `"上一轮尽调 C001"`)。五态里**没有「继承」这一态**,不标的话「上一轮抓过、这轮沿用」与「这轮真的抓了」在数据上完全同形 —— 实测 5 张卡标着 `fetch_state: ok` + 本轮 `as_of`,而整轮从未打开过那份源 PDF。`card_check` 现在会按措辞给 WARN;**要么补字段,要么本轮真的回源取证一次**。
- 落卡时对照 `redlines.md` 的**全部**条目(⛔ 别写死编号,以规则库为准);新的口径混用风险 → 记红线候选(带具体数字与来源 uid),之后进资料汇编的边界层。
- 随手自检:`card_check.py` 有 FAIL 先修卡再继续。

**汇编(聚合发生在这里,不在卡上)**
- 强度按 aggregation.md 推导并落 `rule_trace`;规则外判断写 `override_reason`;B 级为主的主张强度**上限 medium**;禁止伪精确(D7)。
- 归因纪律(D12):禁单因归因;同期发生 ≠ 因果;「最多/第一」类比较级须有可比排名支撑,否则降格表述。
- 反例(counter 卡)按显式标准纳入,否则降称「边界案例」(D6)。
- gate 层判定纪律 = 落在预注册空间内,**或有书面修订记录**(D15),严禁写成「必须落在空间内」。
- 质量底线参照规格③「质量底线」:六层齐 · 结论层 ≥5 条 · 边界层 ≥5 条 · 索引 = 去重来源 · 每卡带链接 · 每节有锚点。

**执行**
- **长执行子代理必须后台**(⛔ 禁止 `run_in_background: false` —— 前台没有 report 通道,「11 分钟零输出」的实测成因)+ **每出一个中间结论 `report` 一次**;进长执行段前 `todo_write` 铺步骤;多阶段扇出优先 `workflow`。

## 确认之后又要补资料(⚠ 最容易违规的地方)

资料汇编确认之后要补材料,或你发现须补证:照下面「重新确认一份已经确认过的材料」做(资料汇编推进到 `gate2_awaiting`),中间补卡、改资料汇编,三点的改动内容写明补了什么、结论动没动;弹资料汇编卡照上面「资料汇编写好」的 1–4 步。作废与重新确认**不可跳**(pipeline_status / cite_check 会拦确认之后又改过的材料)。提纲若已确认过:资料汇编确认之后,提纲也照同一套做法再确认一次 —— 补的资料动了提纲就按 outline-cocreate 改,没动就改动内容写「没有改动」。

**重新确认一份已经确认过的材料**(它要改,或者前面的材料重新确认之后它要跟着再确认一次)—— 三份 skill 用同一套做法:① `python -X utf8 "<toolkit>/scripts/stamp.py" "<那份材料>" --invalidate --why "<为什么>"`(旧的确认记录挪进 revision_log,它自己加一条,`v` = 当前版本加一);② frontmatter 的 `version` 加一,与那一条的 `v` 对齐;③ 改要改的地方,三点的改动内容照实写 —— 内容没动就写「没有改动」(可以带一句为什么要重新确认),只改了措辞就写「只改了措辞」,改了别的就写改了什么;④ `python -X utf8 "<toolkit>/scripts/stamp.py" "<project>/task_plan.md" --advance gate1_awaiting`(任务计划)/ `gate2_awaiting`(资料汇编)/ `gate3_awaiting`(提纲),再弹它的确认卡。
